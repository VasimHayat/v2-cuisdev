## Timestamps in plain terms

A Unix timestamp counts the seconds since 1 January 1970 UTC. It is the common language of logs, databases, APIs and tokens because it is a single number that means the same instant everywhere. The trouble starts when a person needs to read one, or when systems disagree on the unit: JavaScript speaks milliseconds, Python and PostgreSQL often microseconds, Go and observability tools nanoseconds.

This converter reads all of them. Paste a value and it tells you which unit it assumed, then shows the instant in every format you are likely to need, from ISO 8601 for an API payload to an Excel serial date for a spreadsheet.

## Seconds, milliseconds and the year 2038

The number of digits gives the unit away for any date in the last few decades and the next few centuries: 10 for seconds, 13 for milliseconds, 16 for microseconds and 19 for nanoseconds. Mixing them up produces dates in 1970 or in the year 50,000, which is a quick tell when debugging. Systems that still store seconds in a signed 32-bit integer will overflow in January 2038; 64-bit storage, which this tool assumes, pushes that problem out by billions of years.

## Time zones and daylight saving

An instant has one Unix value but a different wall-clock reading in every zone, and that reading moves when a zone switches to or from daylight saving time. Pick any IANA zone and the converter shows its offset on that exact date, formats the time with that offset, and lets you edit the date and time as someone in that zone would see them.
