faq:
  - q: What shape does my JSON need to be?
    a: "An array of objects, one object per row, such as [{\"name\": \"Ada\"}, {\"name\": \"Linus\"}]. If an API wrapped the array in an envelope such as {\"data\": [...]}, the converter finds the first array of objects inside and uses it. A single object can be converted by wrapping it in square brackets, and an array of plain values becomes a one-column table."
  - q: How are nested objects and arrays converted to CSV?
    a: "Nested objects are flattened into dot-notation columns, so {\"address\": {\"city\": \"London\"}} becomes a column named address.city. Arrays are written as JSON text inside a single quoted cell, because CSV has no way to represent a list in one column. Null values become empty cells. Columns appear in the order they are first seen across all rows."
  - q: Can I convert CSV to JSON without a header row?
    a: "Yes. Switch the direction, untick First row is header, and every line becomes an array of strings, giving you a JSON array of arrays. Tick it again and each row becomes an object keyed by the column names, with duplicate names renamed and reported."
  - q: Why are numbers in quotes in the JSON output?
    a: "CSV has no types, so by default every value stays a string to avoid changing your data, for example turning the ZIP code 02134 into 2134. Tick Detect numbers to convert values that look like numbers or true and false into JSON numbers and booleans."
  - q: Which delimiters are supported and how is one detected?
    a: "Comma, semicolon, tab and pipe. When reading CSV with the delimiter set to Auto-detect, the parser samples the first rows and picks the character that produces a consistent number of fields. If detection fails you get a note and a comma is assumed; choose the delimiter explicitly to override it. Excel in many European locales exports with semicolons."

## From API response to spreadsheet

JSON is how APIs talk; CSV is how spreadsheets and databases import. Converting between them is a daily chore that usually involves a script and some surprises around nested fields. This converter does the flattening for you: each object becomes a row, each key becomes a column, and nested objects contribute columns named by their path, so `address.city` and `address.country` sit beside `name` as you would want them in a sheet.

Columns are ordered by first appearance. If the third record has a field the first two lack, it becomes a new column at the end and the earlier rows get empty cells, which is the behaviour spreadsheets expect.

## Going back from CSV

The same page converts CSV to JSON. Delimiter detection handles comma, semicolon, tab and pipe files, so an export from a European Excel installation works without changing a setting. Values stay strings unless you ask for typing, which protects leading zeros, phone numbers and identifiers. Rows with the wrong number of fields are reported as warnings with their line numbers, so you can fix the source instead of discovering a shifted column later.

## Quoting rules

Output follows RFC 4180: fields containing the delimiter, a quote or a line break are wrapped in double quotes, and quotes inside a field are doubled. Turn on Quote all when a downstream tool insists on quotes around every field, which some import wizards do.
