## What makes JSON invalid

JSON has a deliberately tiny grammar: objects, arrays, strings, numbers, true, false and null. Everything else is an error. The strictness is what makes JSON portable across every language, but it also means a document that looks fine to a human can still be rejected by a server.

The validator parses your text with the same rules a browser or API uses and shows you the first problem it meets. Fix it and run again; most documents have only one or two issues.

## The five mistakes that cause most errors

1. **Trailing commas.** `{"a": 1,}` is invalid. Remove the comma after the last item.
2. **Single quotes.** `{'a': 1}` is invalid. Use double quotes for keys and string values.
3. **Unquoted keys.** `{a: 1}` is invalid. Keys must be strings in double quotes.
4. **Comments.** `// note` and `/* note */` are not allowed. Strip them before sending.
5. **Special values.** `undefined`, `NaN` and `Infinity` are not JSON. Use `null` or a number.

## Validate before you ship

Invalid JSON in a config file can take down a deploy; in an API response it breaks every client at once. Pasting the document here before committing or publishing takes a few seconds and removes an entire category of production incidents. When the document passes, the [JSON Formatter](/tools/developer/json-formatter/) will make it readable and the [JSON Minifier](/tools/developer/json-minifier/) will make it small.
