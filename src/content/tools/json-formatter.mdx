faq:
  - q: What is the difference between a JSON formatter and a JSON beautifier?
    a: Nothing. Both terms describe the same operation of adding consistent indentation and line breaks to JSON so humans can read it. "Pretty print" is a third name for the same thing.
  - q: Will formatting change my data?
    a: No. Formatting only changes whitespace outside of strings. Values, key order (unless you tick Sort keys) and types are preserved exactly.
  - q: Why does Format do nothing?
    a: The input is not valid JSON yet. The error is underlined and shown beneath the editor; fix it or accept the automatic repair, then Format again.
  - q: Which indentation should I use?
    a: Two spaces is the most common choice in JavaScript projects and the default for tools like Prettier. Four spaces is typical in Python and Java teams. Use whatever your project already uses.
  - q: Is my JSON sent to a server?
    a: No. Formatting happens in your browser. Nothing is uploaded, logged or stored.

## Why format JSON

Minified JSON is perfect for machines and useless for people. A single 40 KB line from an API response is impossible to scan for the field you need. Formatting adds line breaks and indentation so the structure becomes visible: which keys belong to which object, how deep the nesting goes, where an array starts and ends.

This formatter does it live. Paste on the left, read on the right. There is no submit button and no page reload.

## Formatting and version control

Teams that commit JSON files (package manifests, translations, fixtures, infrastructure config) benefit from a consistent style. A formatter with key sorting produces the same output for the same data every time, so a diff shows only the real change instead of a reshuffled file. Many teams run a formatter as a pre-commit hook for exactly this reason.
