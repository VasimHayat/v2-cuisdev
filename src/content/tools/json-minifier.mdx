  - q: How much smaller will my JSON be?
    a: Typically 20 to 40 percent for formatted documents, depending on indentation depth and how long the strings are. The status bar shows the exact figure for your input.
  - q: Should I minify JSON in my repository?

## When minified JSON matters

Every byte an API returns is a byte the client has to download and parse. Formatted JSON carries indentation and newlines that machines do not need. Minifying removes them, which cuts transfer size, speeds up parsing on slow devices and keeps you under size limits in places like HTTP headers, local storage and message queues.

## Minify versus compress

Minification and compression solve different problems. Minification deletes characters that carry no information. Compression (gzip, Brotli) encodes repeated patterns more efficiently. A minified document compresses better than a formatted one, so the right answer is almost always to do both: minify at build time, compress at the server.

## Going back

Minified JSON is hard to read. If you need to inspect a compact document, paste it into the [JSON Formatter](/tools/developer/json-formatter/) and it becomes readable instantly. The [JSON Editor](/tools/developer/json-editor/) does both in one place.
