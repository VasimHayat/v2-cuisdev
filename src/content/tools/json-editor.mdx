## What this JSON editor does

JSON (JavaScript Object Notation) is the format behind almost every web API, config file and data export you will touch as a developer. It is simple to read, but one missing comma or stray quote breaks the whole document, and the error messages browsers and servers give you are rarely helpful.

This editor fixes that. As you type or paste, it parses the document and underlines the first problem. The status bar tells you the line, the column, what went wrong and, for the common mistakes, how to fix it. Once the document is valid you can format it for reading, minify it for shipping, sort keys for clean diffs, and copy or download the result.

## Common JSON errors and what they mean

- **Unexpected token } or ]** usually means a trailing comma after the last property or item. JSON does not allow it.
- **Unexpected token '** means single quotes. JSON strings and property names must use double quotes.
- **Unexpected token in property name** means an unquoted key, such as `{name: "x"}` instead of `{"name": "x"}`.
- **Unexpected end of input** means the document stops early. A closing `}` or `]` is missing.
- **Unexpected token /** means a comment. Strict JSON has no comments. Remove them or use a JSONC-aware tool.

## Formatting options explained

Two-space indentation is the default used by most JavaScript projects, Prettier and GitHub. Four spaces is common in Python and Java codebases. Tabs let every reader choose their own width. Sorting keys alphabetically makes two versions of the same document easy to compare in a diff tool, which is why many teams sort configuration files before committing them.

## When to minify

Minifying removes every space, tab and newline that is not inside a string. The result is identical data that is typically 20 to 40 percent smaller. Use it for API responses, bundled config, and anything stored in a size-limited field. Keep the formatted version in your repository where humans read it.
