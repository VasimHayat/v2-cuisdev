    a: "Text is first turned into bytes by a character encoding, almost always UTF-8. Each byte is a number from 0 to 255, which is then written in base 2 as eight binary digits. The letter H is byte 72, written 01001000. The tool does both steps and lets you change either one."
  - q: Why does one character produce several bytes?
    a: "UTF-8 uses one byte for ASCII letters and digits, two bytes for most accented letters such as é, three for most other scripts and symbols, and four for emoji. The byte table shows exactly which bytes each character becomes."
  - q: What is the difference between bytes and code points?
    a: "A code point is the number Unicode assigns to a character, written like U+00E9 for é. Bytes are how that number is stored in a particular encoding. Code points are the same in every encoding; bytes are not. Choose Code points when you want the Unicode numbers rather than the stored bytes."

## Text is stored as numbers

Computers store text as bytes, and bytes are just numbers from 0 to 255. Seeing those numbers is useful when you debug an encoding problem, read a protocol dump, write a test fixture, or explain how text works. This converter shows the numbers in whichever base you need: binary for teaching and bit-level work, hexadecimal for debugging and protocols, octal for old escape sequences, decimal for byte arrays in code.

## Encodings matter

The same text produces different bytes in different encodings. In UTF-8, the word café is five bytes, because é needs two. In Latin-1 it is four. In UTF-16 every character takes at least two bytes. Picking the wrong encoding when decoding is the usual cause of mojibake, the garbled characters you see when a file is read with the wrong settings. Switch the encoding here to see the difference immediately, and use the byte table to inspect a single character.
