Use v7 for primary keys in databases, because it starts with a timestamp and sorts in creation order, which keeps B-tree indexes compact. Use v5 when the same input must always produce the same UUID. v1 and v3 exist for compatibility with older systems."
  - q: Are these UUIDs really unique?
    a: "For practical purposes, yes. A v4 UUID has 122 random bits from the Web Crypto API. You would need to generate about a billion UUIDs per second for 85 years to reach a 50 percent chance of a single collision. v7 adds a millisecond timestamp in front of 74 random bits, which makes collisions even less likely across time."
  - q: Why is v7 better than v4 for database keys?
    a: "Random v4 keys land in random places in an index, so every insert touches a different page and the index fragments. v7 keys start with the creation time, so new rows append to the end of the index like an auto-increment integer, while remaining globally unique and safe to generate on clients."

## What a UUID is

A universally unique identifier is a 128-bit number written as 32 hex digits in five groups, such as `2ed6657d-e927-568b-95e1-2665a8aea6a2`. Any system can create one without asking a central server and be confident nobody else will create the same value. That property makes UUIDs the standard choice for database keys in distributed systems, request and trace IDs, file names, and identifiers created on the client before a record is saved.

Four bits of every UUID give its version and two or three give its variant. The inspector on this page reads those bits, and for time-based versions it also recovers the moment the UUID was created.

## Choosing v4 or v7

Version 4 is pure randomness and the safe default. Version 7, standardised in RFC 9562 in 2024, puts a 48-bit Unix millisecond timestamp in front of the random bits. The result sorts by creation time, which databases reward with smaller, faster indexes, and you can read the creation time back from the key itself. This generator keeps a counter inside each millisecond, so a batch of v7 UUIDs is strictly increasing even when thousands are created at once.

Name-based versions are different in kind: they are not random at all. A v5 UUID for the DNS namespace and `www.example.com` is the same on every machine, forever, which is exactly what you want when mapping an existing identifier to a UUID.
